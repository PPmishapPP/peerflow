# План: проверка фазы 1 на реальном устройстве через тестовый сервер

Дата: 20.11.2026

## Overview

**Что делаем.** Поднимаем сервер PeerFlow на доступном VPS (`demiapp.ru`),
чтобы Android-приложение на реальном устройстве работало не через эмулятор, а
через настоящий сервер в интернете. Постоянный кооперативный сервер
(`mayakspace.com`) пока недоступен — используем `demiapp.ru` как временную
площадку.

**Зачем.** Фаза 1 (регистрация, вход, заявки на вступление, голосование) готова,
но проверялась только на эмуляторе/локально. Нужна проверка на живом устройстве
и по настоящей сети, включая TLS.

**Как встраивается.** В `backend/` добавляются файлы развёртывания (образ,
compose, конфиг nginx); в `android/app/build.gradle.kts` адрес сервера
становится переопределяемым при сборке. Продуктовые правила не меняются,
требования `BR-…` не затрагиваются.

## Контекст (из разведки)

- Сервер `demiapp.ru` (144.31.48.212, Ubuntu 24.04, 2 vCPU, ~2 ГБ RAM, Docker,
  хост-nginx на 80/443 + TLS). Рядом работает другое приложение (`groupdating`).
- Свободны порты 8082 и 8443. SSH-доступ к GitHub у сервера есть.
- Сертификат `demiapp.ru` покрывает только `demiapp.ru` (без wildcard).

**Принятое решение (вариант C):** тот же домен, отдельный порт **8443** с
существующим сертификатом `demiapp.ru`. Поддомен и новые DNS-записи не нужны.

## Development Approach

- Изоляция: у PeerFlow свой каталог `/opt/peerflow`, свой compose, своя сеть,
  свои тома и `.env` — соседнее приложение не трогаем.
- Наружу открыт только `8443`; backend слушает `127.0.0.1:8082`.
- Секреты — только в `.env`, в репозиторий не попадают.
- Память JVM ограничена (`-Xmx256m`): хост делят два приложения.

**Решения по ходу:**
- Порт `8443`, а не поддомен: сертификат `demiapp.ru` покрывает только это имя,
  поддомен потребовал бы правки DNS. Хост тот же — сертификат подходит как есть.
- Сертификат `demiapp.ru` истекал 21.11.2026, автопродление было сломано
  (`standalone` конфликтовал с nginx за порт 80) — починено и продлено досрочно.
- `Xmx256m`: хост делят два приложения, у хоста ~2 ГБ RAM.
- Debug-сборка ходит по `https://` — разрешение cleartext ей не нужно; в коде
  ничего менять не пришлось, только адрес при сборке.
- Готовый APK — `android/app/build/outputs/apk/debug/app-debug.apk` (адрес
  `https://demiapp.ru:8443/` внутри `BuildConfig`).

**Что сделано на сервере (вне репозитория):**
- `/opt/peerflow` — каталог развёртывания: `.env` (600); данные — в named

- Стек `peerflow`: `peerflow-postgres-1` (volume `peerflow_postgres_data`) и

- `/etc/nginx/sites-available/peerflow` + симлинк в `sites-enabled`.
- Бэкапы изменённых файлов nginx и certbot — в `/root/backups`.

### Task 7: Исправление 500 при загрузке аватара

**Симптом:** регистрация с телефона падала с «попробуйте позже» — сервер
отвечал `500 «Не удалось сохранить файл»` только при наличии аватара.

- [x] найдена причина: каталог `/opt/peerflow/storage` на хосте принадлежал
      `root`, а приложение пишет под `peerflow` (uid 1001) — запись запрещена
- [x] `compose.prod.yaml`: вложения перенесены в named volume `attachments`
      (фактическое имя — `peerflow_attachments`; Docker выставляет владельца
      из образа) вместо bind-mount
- [x] `deploy.sh`: добавлена проверка записи в `/app/storage` после запуска
- [x] документация и `.env.example` обновлены (named volume вместо каталога)
- [x] проверено сквозной регистрацией с аватаром через публичный HTTPS (`201`)

**Решение:** bind-mount host-каталога требовал ручного `chown` и ломался при
следующем развёртывании; named volume снимает проблему владельца навсегда.
