# PeerFlow — приложение (Android)

Android-приложение сообщества. Внутри две части:

- **Рабочий слой** — вход, регистрация, заявка на вступление и предложения
  (список, создание, голосование), а также голосование за приём новых членов
  работают через настоящий сервер (`backend/`): Retrofit + JWT, состояние в
  ViewModel.
- **Демо-прототип** — остальные экраны пока на вымышленных данных в памяти.
  Цель прототипа — за 5–10 минут показать механику PeerFlow на живом примере.

Дальше по плану (`docs/plans/`) демо-экраны по одному переводятся с демо-данных
на сеть; первые пять уже переведены.

## Что уже ходит на сервер

| Экран | Что умеет | Требования |
|---|---|---|
| Вход | Логин и пароль, ошибки сервера по-русски | `BR-JOIN-1` |
| Регистрация | Логин, пароль, имя, «о себе», аватар | `BR-JOIN-1` |
| Вступить в сообщество | Текст заявки, своя заявка и её статус | `BR-JOIN-2`, `BR-JOIN-5` |
| Список предложений | Секции «В работе» / «На обсуждении», сортировки | `BR-RANK-4`, `BR-RANK-5` |
| Новое предложение | Тема, описание и обязательный бюджет | `BR-OVER-2`, `BR-BUDGET-2` |
| Карточка предложения | Голос «делаем / не делаем» и его смена | `BR-VOTE-4`, `BR-VOTE-13` |
| Заявки на вступление | Очередь заявок, голос «принять / отклонить» | `BR-JOIN-5`, `BR-VOTE-8` |

Токен хранится в `TokenStore` и подставляется в каждый запрос через
`AuthInterceptor`. При старте `SessionViewModel` спрашивает `GET /api/auth/me`:
если токен протух — уводит на вход, если человек ещё не принят в сообщество —
на экран заявки.

### Адрес сервера

`BASE_URL` приходит из `BuildConfig`:

| Сборка | Значение |
|---|---|
| `debug` | `http://10.0.2.2:8080/` — это localhost компьютера с точки зрения эмулятора |
| `release` | `https://mayakspace.com/` |

Оба значения можно переопределить при сборке, не правя код:

```powershell
# Проверка на устройстве в локальной сети (бэкенд на компьютере):
.\gradlew.bat :app:assembleDebug -PpeerflowDebugBaseUrl=http://192.168.1.10:8080/

# Проверка на сервере:
.\gradlew.bat :app:assembleRelease -PpeerflowReleaseBaseUrl=https://demiapp.ru:8443/
```

Разрешение открытого HTTP выдаётся только в debug-манифесте
(`app/src/debug/AndroidManifest.xml`), в release-сборке cleartext запрещён.
Если сервер запущен на телефоне по кабелю, а не на эмуляторе, `BASE_URL`
задают через `-PpeerflowDebugBaseUrl` (см. выше).

## Сценарий демонстрации (демо-прототип)

Прототип проходит по одному сквозному сюжету сообщества «Маяк»:

1. **Боль** — имитация обычного мессенджера. Тема «Аренда помещения для
   лекции» тонет среди 1024 сообщений о «борьбе с 5G-вышками».
2. **Новое предложение** — кнопка «+» на списке: тема, описание и обязательный
   бюджет. Внесённое предложение сразу появляется в «На обсуждении».
3. **Список предложений** — разделён на секции «В работе» (есть лидер и бюджет)
   и «На обсуждении». Сверху живая дискуссия («Аренда помещения»), внизу
   заминусованное «Борьба с вышками 5G». Никого не банили — шум сам осел вниз.
   Есть сортировки «Популярные / По бюджету / Новые».
4. **Карточка в работе** — лидер, остаток доверия и кнопка **«Забрать свою
   легитимность»**: доверие можно вернуть в любой момент. Ниже 70% — мандат
   теряется.
5. **Обсуждение** — реакции `+ / − / спам`, сортировка «Популярные / Новые»,
   вложенные ответы, скрытый спам. Решение «делаем / не делаем», кандидаты в
   лидеры и их легитимность.
6. **Отчёт лидера** — отчёт с прикреплённой квитанцией и обсуждение под ним.
7. **Закрытие задачи** — сообщество голосует «выполнено / нет», оставшаяся
   легитимность лидера переходит в репутацию.
8. **Профиль** — репутация, кому и по каким задачам передана легитимность.

## Как запустить

### Одной командой: собрать и поставить на телефон

```powershell
cd android
.\deploy.ps1          # тесты → сборка под тестовый сервер → установка → запуск
```

Скрипт делает всё сразу и не требует помнить про адрес сервера: по умолчанию
APK собирается под `https://demiapp.ru:8443/`. Если телефон не подключён, он всё
равно соберёт APK и покажет путь к файлу — можно перекинуть вручную.

| Ключ | Что делает |
|---|---|
| `-BaseUrl <адрес>` | другой сервер, например `-BaseUrl http://192.168.1.10:8080/` |
| `-Serial <номер>` | какое устройство взять, если подключено несколько |
| `-SkipTests` | не прогонять тесты перед сборкой |
| `-NoLaunch` | установить, но не открывать приложение |
| `-Release` | собрать release вместо debug (нужна настроенная подпись) |

`adb` скрипт находит сам: сначала в `PATH`, затем в SDK из `local.properties`.

### Вручную

Нужен запущенный Android-эмулятор (например, AVD `muraveinik`) или устройство.

```powershell
cd android
.\gradlew.bat :app:installDebug
adb shell am start -n ru.peerflow.demo/.MainActivity
```

Сборка APK:

```powershell
.\gradlew.bat :app:assembleDebug -PpeerflowDebugBaseUrl=https://demiapp.ru:8443/
# результат: app\build\outputs\apk\debug\app-debug.apk
```

> Без `-PpeerflowDebugBaseUrl` debug-сборка смотрит на `http://10.0.2.2:8080/` —
> это localhost компьютера с точки зрения эмулятора, и на реальном телефоне
> приложение не найдёт сервер.

Release-сборка (`assembleRelease`) сейчас **не собирается** из-за сети: Gradle не
может скачать `lint-gradle` с `dl.google.com` (задача
`lintVitalAnalyzeRelease`). Кроме того, в `app/build.gradle.kts` нет
`signingConfig`, поэтому даже успешная release-сборка дала бы неподписанный APK,
который телефон не установит. Для проверки на устройстве используйте debug.

## Тесты

```powershell
.\gradlew.bat :app:testDebugUnitTest
```

96 модульных тестов, все зелёные. Что проверяют:

- механику правил: сортировку предложений, порог скрытия спама (3 метки),
  порог удержания легитимности (70%);
- ViewModel входа, регистрации, заявки, очереди заявок на приём, сессии,
  списка предложений, карточки и новой заявки — на фейках репозиториев, без
  сети и Android-рантайма.

Тесты ViewModel опираются на три приёма:

- `MainDispatcherRule` подменяет `Dispatchers.Main` на тестовый;
- фейки репозиториев (`testing/Fakes.kt`) вместо моков — так видно, какие
  аргументы реально ушли в репозиторий;
- одноразовые события читаются через `async { events.first() }` до действия:
  подписка обязана существовать в момент отправки, иначе событие теряется.

## Технические заметки

- Kotlin 2.3 + Jetpack Compose (Material 3), Hilt, Navigation Compose.
- Сеть: Retrofit 3, OkHttp 5, kotlinx-serialization.
- Собрано на Gradle 9.8.2 / AGP 9.5, компилируется на JDK 21.
- Динамические цвета отключены: демо должно выглядеть одинаково на любом
  устройстве и в записи экрана.
- ViewModel зависят от интерфейсов репозиториев, а не от `PeerflowApi`:
  поэтому тесты не требуют ни сети, ни MockWebServer.
- Валидация на клиенте (`CredentialRules`) повторяет серверную и проверяет
  **обрезанное** значение (`trim()`) — ровно то, что уйдёт на сервер.

## Важное уточнение к метрике популярности

Изначально в бизнес-описании (`docs/peerflow.md`) метрика популярности
предложения была описана как «комментарии + уникальные участники». На демо-данных
она сразу показала изъян: зашумлённое предложение про 5G набирало 412 сообщений и
вылезало на первое место — то есть метрика **награждала спам**.

Поэтому формула была поправлена и в самом документе (`BR-RANK-2`, `BR-RANK-3`):

```
популярность = уникальные участники + (голоса «за» − голоса «против»)
```

Просто объём сообщений популярность больше не повышает — учитываются участники
и поддержка голосами, а не шум.
